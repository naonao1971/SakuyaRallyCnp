# 咲耶ラリーCNP — NOUN RALLY ⌐◨-◨ (proto)

CNP11体を集める Rally-X 系の迷路ゲーム。車は止まらず、曲がる方向だけを決めて
迷路を走り回り、散らばった11体を全部回収するとクリア。

`index.html` を開くだけで動く。ビルド不要、依存ライブラリなし。

姉妹作の [咲耶スクランブル](https://github.com/naonao1971/SakuyaScramble)
（横スクロールSTG、[sakuya.naoblock.jp](https://sakuya.naoblock.jp/)）とは
別ゲームだが、**登場する11体はキャラ・名前・絵ともに同じもの**を使っている。

> CNP（CryptoNinja Partners）の非公式ファンアート作品です。公式とは関係ありません。

## 遊び方

- 車は止まらない。**曲がる方向だけ決める**
- 迷路に散らばった CNP 11体を全部回収すると**出口が開く**。出口へ戻ればクリア
- **通った場所にタイヤ痕が残り、1マスにつき加点**される。同じマスは二度加点しない
- 画面上段に**11体のロスター**が並ぶ。取った枠は絵が起き、まだの枠はシルエット
- 赤い敵車に触れるとクラッシュ。**車は3台**あり、ぶつけても続きから走れる
- クラッシュしても CNP・スコア・迷路は引き継ぐ。自機と敵の配置だけ戻り、**復活後2秒は無敵**
- `SMOKE` で敵をスピンさせられるが、燃料を多く食う
- 燃料が尽きても即死しない。**減速する**（自機 2.625 → 1.75）ので敵に抜かれ、いずれ捕まる

| 操作 | PC | スマホ |
| --- | --- | --- |
| 曲がる | 矢印 / WASD | 画面を押したまま倒す（バーチャルスティック） |
| 煙 | Space | SMOKE ボタン |
| 音の入切 | M | 🔊 ボタン |

スコアの内訳。

| | 得点 |
| --- | --- |
| CNP n体目の回収 | `100 + n*20` 点（11体で合計 2420 点） |
| タイヤ痕 1マス | `PAINT_PTS` = 5 点（通路は約446マス＝最大 2230 点） |
| 出口へ到達 | `GOAL_BONUS` = 800 点 |

**CNPとゴールは全員同じ点なので、クリアした人どうしの差は塗りだけでつく。**
以前は全クリアすると誰でも必ず 2420 点で同着だった。ベストスコアは
`localStorage` に残る。

## `localStorage` を素のまま呼ばないこと（STARTが効かなくなる）

**`localStorage` は「あるのに触ると落ちる」ことがある。** 別オリジンの iframe で
動かしたとき（アーティファクト等）、iOS Safari の「サイト越えトラッキングを防ぐ」
（既定でオン）が効いていると、**`getItem` を呼んだ瞬間に `SecurityError`** が飛ぶ。

初期化の途中でこれを踏むとスクリプトがその行で死に、**以降の
`addEventListener` が1つも走らない**。HTML と CSS は生きているので画面は
いつも通りに見え、**STARTを押しても何も起きない板**になる。原因がどこにも
出ないので、見つけるのに時間がかかる。実際に踏んだ。

必ずこのラッパー越しに使うこと。

```js
const store = {
  get(k){ try{ return localStorage.getItem(k); }catch(e){ return null; } },
  set(k,v){ try{ localStorage.setItem(k,v); }catch(e){} },
};
```

再現の仕方（Playwright）:

```js
await ctx.addInitScript(()=>{
  Object.defineProperty(window,'localStorage',{configurable:true,
    get(){ throw new DOMException('The operation is insecure.','SecurityError'); }});
});
```

`sessionStorage` / `indexedDB` も同じ。**ブラウザの機能を初期化の本流で
素のまま呼ばないこと。**

## 向きの監視は「すべての宣言が終わってから」始めること

`updateOrientation()` は `state` と `bgmOn` を触る。この関数は画面の向きを扱う
都合でファイルの先頭近くに置いてあるが、**先頭で呼んではいけない**。
`state`（宣言は 300行目あたり）も `bgmOn`（700行目あたり）も `let` なので、
そこに届く前に読むと **TDZ で `ReferenceError`** になり、**スクリプトがそこで死ぬ**。

死んだ先が「STARTを押しても何も起きない板」なので、原因がまるで見えない。
**実際に踏んだ。**

**横で開くと踏まない。** `if(should===orientationBlocked) return;` があり、横持ちでは
`should` も `orientationBlocked` も `false` なので早期 return して `state` に届かない。
**縦で開いた実機だけが死ぬ。** 手元のテストは横から始めていたので、ずっと気づけなかった。

- 監視の開始（リスナー登録・`setInterval`・最初の1回）は **IIFE の末尾**で行う
- 念のため `var booted` で守る。`var` は巻き上げで `undefined` になるので、
  最初期に読んでも TDZ にならない（`let` にすると同じ罠に戻る）

### 画面まわりのテストは必ず「縦で開いて横にする」を通すこと

実機の流れは **縦で開く → 警告を見る → 横にする → START**。横から始めるテストでは
この経路が一度も通らない。`rotate.mjs` に入れてある。

| | 縦→横 | 横だけ |
| --- | --- | --- |
| 直す前 | **START が効かない** | 動く |
| 直した後 | 動く | 動く |

## 初期化で落ちたら画面に出すこと

上の件は「黙って死ぬ」のが一番たちが悪かった。本体より**前**に
`error` / `unhandledrejection` を拾う小さなスクリプトを置き、
`#crash` の帯にメッセージを出している。押すと消える。

本体より前に登録すること ― 本体の中で登録しても、本体が死ぬ側なので間に合わない。

**出すのは「最初のエラー」にすること。** 2件目以降は1件目で死んだ巻き添えで、
原因から遠ざかる。実際、真因は `bgmOn` の TDZ なのに、あとから 250ms ごとに出る
`state` の TDZ で上書きされ、そちらを追いかけた。いまは1件目を保持し、
`(以後 N件)` と件数だけ添える。

## 出口はスタート地点に置かないこと

11体そろえたあと**わざとクラッシュすれば復活位置＝出口**になり、残機1つで
ゴールを買えてしまう。`farthestCell()` でスタートから幅優先探索して最も遠い
通路マスに置いている。連結性は岩の判定（後述）で保証してあるので必ず到達できる。

11体そろっても**即クリアにしない**。`exitOpen` が立つだけで、そこから出口へ
戻るまでが一走り。戻る道中も塗れるので、最後に得点を伸ばす余地が残る。

## 操作はバーチャルスティック

スマホでは**画面のどこでも触れた場所にスティックが出る浮動式**。押したまま倒すと
その方向へ、離すと操作終了。十字パッドは廃した（150px を場所代に取られるため）。

### 出力は `heldDir` に入れること

スティックは「押している間ずっと続く**状態**」の入力なので、`heldDir` に流し込めば
十字キーを押しっぱなしにしているのと同じ経路を通り、`update()` が毎フレーム予約を
補充する。`WANT_GRACE`（0.25秒）の設計がそのまま効く。

**スワイプ（一回きりの**イベント**）ではこれが成り立たない。** 分岐は 0.19〜0.38秒
ごとに来る（40マップ・73,778サンプルの実測。49%は 0.19秒後）のに対しスワイプ1回は
150〜250ms かかるので、予約の寿命を別途延ばす必要があり、それでも取りこぼす。

### 原点は指に追従させること（トレーリング）

原点を最初に触れた点に固定すると、一方向へ倒したときのズレが残り続け、**直角へ
変えるのに指を90px動かす必要があった**。原点を指から半径 `JOY_R` 以内へ引きずると
30px で変わる（実測。3分の1）。

### 斜めでばたつかせないこと

素朴に `|dx|>|dy|` で4方向へ量子化すると、45度付近で毎フレーム左右に切り替わる。
別の軸へ乗り換えるには `JOY_HYST` 倍の優勢を要求する。実測では 1.0 で23回/秒
ばたつき、1.18 以上で 0 回。

### `wantFresh` は向きを変えた瞬間だけ立てること

毎フレーム立てると後退（Uターン）の門が開きっぱなしになり、以前直した
「勝手なUターン」が戻ってくる。

## 音

### BGMは必ずオリジナルで書くこと

ラリーXの原曲はナムコの著作物。**作風だけ寄せた自前のループ**を鳴らしている
（`BGM_LEAD` / `BGM_BASS`。8分音符32ステップ＝4小節、数字は MIDI ノート番号で
0は休符）。原曲の旋律を打ち込み直して使ってはいけない。

### AudioContext は必ずユーザー操作の中で解除する

iOS Safari は `AudioContext` を `suspended` で作る。ユーザー操作のハンドラの中で
`resume()` しないと一切鳴らない。最初の `pointerdown` と `keydown` で
`unlockAudio()` を呼んでいる。**ページ読み込み時に作ってはいけない**
（作っても suspended のままで、あとから resume しても鳴らない端末がある）。

### 先読みしてスケジュールすること

`setInterval` の中で「いま鳴らす」方式だとタイマーの揺れがそのまま
リズムの揺れになる。25ms ごとに起き、`actx.currentTime + 0.12秒` までに
入るぶんを **先に予約** している（`bgmTick()`）。

### 矩形波は頭と尻に傾斜をつける

ゲインを立ち上げ・切り下げなしで 0 から出すとプチッと鳴る。
`bgmVoice()` で 8ms の立ち上がりと短い減衰を入れてある。

### ミュートはマスターゲインで行う

スケジュールは止めずに `master.gain` を 0 にする。止めてしまうと解除した
ときにループの位相がずれる。状態は `localStorage` に残す。

燃料が 25 を切ると 8分音符が `STEP_BASE`(0.132秒) から `STEP_FAST`(0.098秒)
へ詰まり、テンポが上がる。

## 壁に突き当たったときの挙動

行き先は地形で決まる。どのケースでも車は止まらない。

| 地形 | 挙動 |
| --- | --- |
| L字路 | 開いている一方へ曲がって先へ進む |
| T字路 | 左右とも開くので既定は**右折**。ただしキー操作をしていればそちらが優先 |
| 袋小路 | 左右とも壁。戻るしかないので**反転** |

キー操作が優先されるのは、予約(`want`)の適用が壁判定より先に走るため。

### 予約(want)の寿命

**キーを押している間だけ予約が生きる。離すと `WANT_GRACE`(0.25秒)で消える。**
消えた状態は `want === null` で表す。

これが無いと「何も押していないのに勝手に曲がる」が起きる。予約が永久に残ると、
一度押した向きが開いているマスに来るたびに曲がり続けてしまう（実測で、→を
1回押して離しただけで20秒間に7回、無入力のまま勝手に曲がった）。

**`want` を `dir` と同じ値にする方式では消したことにならない。** その直後に車が
自動で曲がると `want` と `dir` がズレ、予約として復活する。必ず `null` にする。

後退(Uターン)だけは `wantFresh`、つまり「押したばかり」でないと通さない。
ここで**オートリピートを新しい押下に数えないこと**（`e.repeat` を除外する）。
数えてしまうと、長押し中に自動で2回曲がって向きが真逆になったとき、来た道は
かならず開いているのでUターンが通り、勝手に引き返す。

押したままタブを切り替えると `keyup` が来ないので、`blur` でも保持を解除する。

## 画面の向き

**ゲームは横持ち専用。** 縦持ちのスマホではタイトルと遊び方を出し、横向きを促す。

横持ちレイアウトは**高さ基準**で組んであること。幅基準だと iPhone 横持ちで
133px はみ出す。横持ちは「幅が余って高さが足りない」ので、`#stage` の高さを
`100svh` から決める。

### ステージの大きさは1本の式で決まる

```
height = min(100svh - 34px, 420px, (100vw - 予約) / アスペクト)
```

**アスペクト比・左右の予約幅・右列の中身はすべてこの1本の式に入る**ので、どれか
1つだけ変えると別の端末で破綻する。変えるときは iPhone SE (667×375) と
iPhone 15 (852×393) の**両方で測ること**。SE は横幅が制約、15以降は高さが制約に
なり、**効く変数が逆になる**のが罠。

広げすぎると逆に狭くなる。4:3 では最近の端末で横幅が余っていた（iPhone 15 で
53px）。十字キーがあるうちは 3:2 が上限だったが、廃した今は **16:10** が上限で、
それを超えると横幅の頭打ちが効いて面積が減る。

### オーバーレイは説明文だけを縮ませること（START が押せなくなる）

`#stage` は `overflow:hidden`。`#ov` の中身がステージの背より高くなると、
`justify-content:center` のせいで**上下が同じだけはみ出し、下端が切り落とされる**。
いちばん下にあるのは START / RETRY ボタンなので、**ボタンだけが消えて
「押せない・始まらない」**になる。見えないので原因も分かりにくい。

実際に踏んだ。説明文が10行まで育った時点で必要な高さは 308px。ステージは
iPhone SE 横で 329px しかなく、残り 18px。アーティファクトのように上下に
枠が付く環境ではそれだけで足りなくなり、ボタンが枠外へ出ていた。

| ステージの高さ | 修正前 | 修正後 |
| --- | --- | --- |
| 329px | ボタン下端が 1px はみ出し | 40px 余裕 |
| 297px | 15px はみ出し | 24px 余裕 |
| 277px | 25px はみ出し（当たり判定がフッターに） | 19px 余裕 |
| 201px | ― | 19px 余裕 |

直し方は**縮んでよいものを1つだけ決める**こと。

```css
#ov h2{flex:0 0 auto;}                      /* 見出しは縮ませない */
#ov p {flex:0 1 auto;min-height:0;overflow-y:auto;}  /* ここだけ縮む */
#btn  {flex:0 0 auto;}                      /* ボタンは死守 */
```

`min-height:0` が要る。**flex アイテムは既定で中身より小さくならない**ので、
これが無いと `overflow-y:auto` を付けても縮まずにはみ出す。

説明文も 10行 → 8行 に削った。ルールが増えるたびに1行足していたが、
スタート画面はステージの高さという上限を持っている。**1行足すときは
1行削る**こと。

### 右列は「ステージが使えなかった余り」だけを吸う

`#stage{flex:0 0 auto}` / `#side{flex:1 1 auto; max-width:172px}`。ステージは
縮まない側なので、横幅が制約になる端末（iPhone SE）では右列が最小幅で止まり、
ステージは削られない。172px の上限は縦から決めた（立ち絵 0.75W ＋ レーダー
0.76W ＋ ボタン ＋ 隙間 が画面高に収まる上限）。

| 端末 | ステージ | 右列 | レーダー |
| --- | --- | --- | --- |
| iPhone SE (667×375) | 527×329 | 120px | 7.0px/マス |
| iPhone 13/14/15 (852×393) | 574×359 | 172px | 10.2px/マス |
| iPhone 15 Pro Max (932×430) | 634×396 | 172px | 10.2px/マス |

縦持ちの判定を**イベント任せにしないこと**。iOS Safari の `orientationchange` は
ビューポート（＝メディアクエリ）の更新より先に発火することがあり、その時点の古い値で
固定すると横向きに戻しても再評価されず、遊べないまま固まる。イベントに加えて
250ms 間隔でも再評価している。

## 配色

咲耶カラーのピンクを基調にする。ただし**危険色（敵車・燃料警告）は橙赤 `#FF4D2E`
へ逃がすこと**。ピンクのまま赤を使うと、自機のマゼンタ・CNPの紫〜桃のhue
（トワ262 / エマ292 / マカミ322 / タルト352）と混ざって「危険」が読めなくなる。
咲耶スクランブルも `magenta #FF2D9B` と `danger #FF4D2E` を別に持っている。

自機は**漆黒の車体＋マゼンタのリムライト**。ピンクを自機だけの徴にしてある。

壁の色を変えるときは、**11体すべてが背景から見分けられるかを確認すること。**
明るい紫（`#6b5588`）にしたときはトワのコントラスト比が 1.43 まで落ちた。
現在の `#5f3a5f` では全11体が比 2.0 以上ある（最悪はトワの 2.08）。

## 描画まわりのメモ

- **自機は ⌐◨-◨ カー**。`drawNoggles()` は咲耶スクランブルの同名関数と同じ作り。
  車体は進行方向に回すが、**ノグルズは回さない**（真上から見た車が曲がっても
  ⌐◨-◨ の顔が常に読めるようにするため）
- **名札**は幅を名前の実測に合わせてある。固定幅だと `TILE=24` より広がり、
  隣のマスのキャラの名札と重なって両方読めなくなる。それでもぶつかる場合は
  先に置いた名札を避けて逃がす。頭上に出すと HUD 帯（`y<22`）に潜る位置の
  ときは、最初から足元側に出して下へ逃がす
- キャラは暗い路面に沈むので、`hue` のオーラを下に敷いている
- **ロスターの未収集枠に「?」の仮絵を出さないこと。** あれは素材未配置を知らせる
  開発用の絵で、「まだ取っていない」の意味に流用すると**11枠が全部同じ顔**になり、
  あと誰が残っているのか読めなくなる。実際の絵から作ったシルエット
  （`silhouette()`）を出す。これは咲耶スクランブルの `drawRescueRoster()` が
  同じ失敗を踏んで得た教訓
- **ロスターは canvas の中の HUD 帯に置く。** ステージの外に帯を作ると
  レイアウトの高さを食い、ステージ全体が縮んでタイルまで小さくなる
  （実測で iPhone 15 が −16%）。canvas 内なら寸法は変わらず、犠牲になるのは
  見える迷路の縦 11.5% だけで済む
- **HUD帯の下に迷路を描かないこと。** 半透明の帯を重ねるだけでは迷路もCNPも
  名札も透けてロスターと混ざる。さらにカメラは自機を中央に置くので、迷路の
  最上段では自機が y=36 に来て **44pxの帯の真下に隠れる**。
  描画領域そのものを `VIEW_H = VH - HUD_H` に下げ、`clip()` で切り落とし、
  カメラも `VIEW_H` 基準にする。帯は不透明でよい（下に何も無いので）
- **自機を動かしたら直後にカメラも合わせること（`syncCam()`）。**
  `crash()` は `update()` を途中で `return` するので、ここを呼ばないと
  復活した最初の1フレームだけ古いカメラで描かれ、自機が画面外へ飛ぶ
- 名札の逃がし判定の基準は**描画領域の上端(0)**。世界は帯の下へずらして
  描くので、帯の高さを足してはいけない
- **タイヤ痕は塗りつぶさない。** `paint` は1マスにつき bit1=横に通った /
  bit2=縦に通った を持ち、通った向きに沿った2本の線で描く。方向を持たないと
  ただの塗り絵になり、走った軌跡が読めない
- **レーダーはコース画面の外（右列）に置く。** 画面内に重ねていたときは自機が
  レーダーの下に潜り、40回中6回（7回に1回）はCNPが見えないまま取りに行っていた。
  外に出すと重なりが起きないので、移動やフェードの処理そのものが要らない
- レーダーのCNPは **3×3px＋白フチで、11体とも同じ位相で点滅**させる。2×2の単色
  ドットでは11体の色が読めない。位相をバラすとチカチカして逆に読めなくなる
- レーダー用 canvas は**実寸×DPRで持つこと**。CSS幅が端末で変わるので、固定の
  内部解像度だとドットが潰れる。`height:auto` の明示も要る（`canvas{height:100%}`
  を受けると `aspect-ratio` が無視されて縦に伸びる）

## 迷路生成で守ること

**岩（`genMaze()` の値 `2`）は通路を塞ぐので、置く場所によっては迷路が分断される。**
分断されると自機からCNPへ到達できず、クリア不可能な盤面になる。

置く前に `countReachable()` で「その1マスぶんしか通路が減らないか」を確かめ、
分断するなら置き直すこと。この判定が無いと、実測で

| | 発生率 |
| --- | --- |
| 1体以上が到達不能（クリア不可能） | 6〜7% |
| 全11体が到達不能（完全に詰み） | 1.5〜1.8% |

つまり**16回に1回はクリアできない迷路**が出る。判定を入れても岩は8個すべて置けて
いて、`newGame()` の所要は 0.5ms。盤面は1プレイに1回しか作らないので、素朴な
探索で十分足りる。

迷路本体（掘削と、その後に壁を26%開ける処理）は分断を作らない。掘削は全体が
つながった完全迷路を作り、壁を開ける処理は通路を増やすだけだから。**分断する
可能性があるのは岩だけ。**

## 調整しやすい定数

```js
const TILE=24, COLS=33, ROWS=25;   // 迷路の寸法
const CHAR_SIZE=22;                // キャラの描画サイズ(px四方)
const CHAR_HIT=14;                 // 回収の当たり判定
```

敵は4台（`placeEnemies()`）、岩は8個（`genMaze()`）、燃料は基本 1.3/秒 + 煙を
出している間 3.2/秒（`update()`）。

塗りとゴールは `PAINT_PTS`（1マス5点）と `GOAL_BONUS`（800点）。

BGMは `BGM_LEAD` / `BGM_BASS`（8分音符32ステップ）と
`STEP_BASE` / `STEP_FAST`（8分音符の長さ）。

ロスターは `ROSTER`（`slot` 20px / `gap` 3px / `y` 24px / `flash` 0.75秒）。
`HUD_H` は `ROSTER.y + ROSTER.slot` = 44px で、HUD帯の高さと名札の逃がし判定の
両方に使う。11枠 × 20px + 隙間 3px = 250px が canvas 614px の中央に収まる。
姉妹作は canvas 960×540 に 36px 枠なので、同じ比率まで落とした値。

スティックは `JOY_DEAD`（12px・無入力の範囲）、`JOY_R`（24px・原点が指を追う
半径）、`JOY_HYST`（1.20・軸を乗り換える優勢比）。

画面は `#stage` の `aspect-ratio:8/5` と canvas の `width=614 height=384`（16:10）。
**両方を揃えること。**

残機は `LIVES_START`（3台）、復活後の無敵は `INVUL`（2秒）。

速度は定数にまとめてある。単位は **60fps 換算の px/フレーム**。

```js
const SPD_PLAYER = 2.625;   // 2.1  * 1.25  実速度 約158px/秒
const SPD_ENEMY  = 2.1875;  // 1.75 * 1.25
const SPD_DRY    = 1.75;    // 1.4  * 1.25  燃料切れ後。敵より遅い
```

1.25 倍は実機で決めた値。**自機と敵の比 1.20 は変えていない**（変えると敵の
脅威度が別物になる）。燃料切れ後の 1.75 も同じ比率で下げてあり、敵
（2.1875）より遅いので必ず追いつかれる。

### 速度はフレームレートに依存させないこと

`stepCar()` と `aiThink()` は、60fps を 1 とするフレーム倍率 `k = dt*60` を
受け取り、`step = speed * k` だけ進む。これを怠って毎フレーム固定量だけ進める
と、**120Hz の端末で2倍速**になる（燃料だけは秒単位で減るため、実質的に難易度
が別物になる）。iPhone / iPad の Pro 系は 120Hz なので実害が出る。

`atCenter()` の**しきい値は必ず `step` と同じ値**にすること。ここがズレると、
重いフレームで中心を飛び越えたのに気づけず、曲がり損ねて壁をすり抜ける。
`dt` は `loop()` で 0.05 秒に制限してあるので `k` は最大 3、1フレームの移動量
は最大 7.9px（2.625*3）で TILE=24 を飛び越すことはない。**速度を上げるときは
この余裕を必ず確かめること**（TILE の半分を超えると壁を抜ける危険がある）。

### 燃料切れの減速は `stepCar()` より前に効かせること

`player.speed` は `update()` の先頭で `fuel>0 ? SPD_PLAYER : SPD_DRY` に
切り替えている。`stepCar()` の後で変えると、`atCenter()` がその
フレームだけ古い速度のしきい値で判定することになり、中心の判定を取りこぼす。

## 残っていること

- スコアのランキング登録（咲耶スクランブルは `apps-script.gs` で Google
  スプレッドシートに出しているが、ラリー側は `localStorage` のベストスコアのみ）
- レア度。咲耶スクランブルには `CNP_TIERS` の5段階（得点・HP回復・出現率）が
  あるが、ラリー側は11体とも同格
- クリア後の X シェア（咲耶スクランブルの `buildShareCardCanvas()` 相当）
- ワープトンネル
- **難易度の再調整。** CNPを最短で追うボット（敵を避けない）で12回試して、
  11体そろったのは1回、出口まで戻れたのは0回。踏破率は平均17%。
  敵4台・追尾72%を緩めるかどうかは要判断
